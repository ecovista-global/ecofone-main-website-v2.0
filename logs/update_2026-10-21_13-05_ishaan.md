## 2. Horizontal Masonry & Strict Swap Drag-and-Drop Architecture

### Fixed 30-Slot Indexing (0 to 29):
- The gallery is bound to exactly 30 slots (`display_order: 0..29`).
- Every filled slot maps directly to an item where `item.display_order === slotIndex`.
- Unoccupied slots render as interactive dashed drop zones that accept new uploads via double-click.

### Block Dimensions & Sizing Paradigm:
| Size Token | Layout Dimensions | Aspect Ratio | Target Use Case |
| :--- | :--- | :--- | :--- |
| `1x1` | 1 column × 1 row (320px × 320px) | 1:1 Square | Partner portraits, customer handovers, product units |
| `2x1` | 2 columns × 1 row (664px × 320px) | ~2:1 Panoramic | Store ribbon-cutting, wide counter views, partner summits |
| `1x2` | 1 column × 2 rows (320px × 664px) | ~1:2 Portrait | Experience center vertical pillars, store facades |
| `2x2` | 2 columns × 2 rows (664px × 664px) | 1:1 Large Square | Flagship milestone banners, headline opening ceremonies |

*Size Storage Mechanism:* The size metadata prefix is stored seamlessly within the caption string (`SIZE:2x1|Grand Opening of New Delhi Saket Experience Center`), ensuring complete backward and forward database compatibility.

### Strict Swap Rules:
1. **Identical Size Swap:** Block `A` swaps directly with Block `B` if and only if both blocks have the exact same size (`1x1` with `1x1`, `2x1` with `2x1`, etc.).
2. **Empty Slot Insertion:** Only `1x1` items can be dropped into an empty slot.
3. **Visual Feedback:** During an active drag:
   - Valid targets glow emerald green with a `"SWAP WITH THIS BLOCK"` banner.
   - Incompatible targets dim out with a `"Size mismatch"` badge.
4. **Collision Detection:** Implemented a resilient multi-tier collision detection pipeline:
   `pointerWithin` -> `rectIntersection` -> `closestCenter`.

## 4. Full-Stack API & Storage Layer

Dual-layer implementation guaranteeing zero downtime and seamless operation across local and production deployments:

### Next.js API Routes (`frontend/app/api/...`):
- `GET /api/gallery`: Public endpoint serving active gallery items sorted ascending by `display_order`.
- `POST /api/admin/gallery`: Creates a new gallery item; handles multipart form data for direct file uploads to `frontend/public/uploads/gallery/` or remote URLs.
- `PUT /api/admin/gallery/reorder`: Atomic reordering endpoint accepting an array of `{ id, display_order }` pairs.
- `PUT /api/admin/gallery/[id]`: Updates caption, size prefix, media URL, or active status.
- `DELETE /api/admin/gallery/[id]`: Removes item from slot.
