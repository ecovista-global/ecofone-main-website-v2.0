## 2. Architecture & Data Flow

```
[EcoFone Admin Console]
         │
         ▼
[BlogsManager Component] ──── (React Portal) ────► [document.body (Modal Layer: z-[100])]
         │
         ├─── GET /api/blogs ────────► [frontend/lib/blogs-server.ts]
         ├─── POST /api/blogs ───────►                 │
         ├─── PUT /api/blogs/[id] ───►                 ▼
         ├─── DELETE /api/blogs/[id] ►      [frontend/data/blogs.json]
         └─── POST /api/blogs/upload ──►    [public/uploads/blogs/]
                                                       │
                                                       ▼
[Public Blog (/blog & /blog/[slug])] ◄── (force-dynamic sync)
```

1. **Storage Layer (`frontend/data/blogs.json`)**:
   - Stores all blog records with metadata: `id`, `slug`, `title`, `excerpt`, `content`, `category`, `placement`, `status`, `imageUrl`, `author`, `readingTime`, and timestamps.
   - Initialized with all 28 existing articles from `frontend/data/blogs.ts`.
2. **Helper Module (`frontend/lib/blogs-server.ts`)**:
   - `getStoredBlogs()` & `saveStoredBlogs()`: Thread-safe reading and writing to `blogs.json`.
   - `getBlogPosts()`: Returns all registry posts.
   - `getBlogPostBySlug(slug)`: Matches posts by both dynamic slug and unique id.
   - `getFeaturedPost()`: Resolves the flagship Hero story.
   - `getRelatedPosts()`: Delivers contextual recommendations by category.

## 4. Modal Stacking Context & Portal Decoupling

### Issue Encountered:
When clicking "+ Create New Blog" or "Delete Article", the background table dimmed with `bg-black/80`, but the dialog box did not appear on screen.

### Root Cause:
1. Ancestor element had `.animate-fade-in` which applied CSS `filter: blur(...)` and `transform: translateY(...)`. Per CSS specifications, any element with a non-none `transform`, `filter`, or `perspective` establishes a new containing block for `position: fixed` descendants.
2. The modal was nested inside `<main className="overflow-y-auto">` containing a table >2,500px tall. The `flex items-center justify-center` rule centered the modal relative to the 2,500px block (~1,250px down the page), placing it completely below the viewport.

### Solution Applied:
- Migrated both the Composer modal and Delete Confirmation modal to React's `createPortal(..., document.body)`.
- Overlays now attach directly to `document.body` with `fixed inset-0 z-[100] w-screen h-screen flex items-center justify-center p-4 bg-black/80 backdrop-blur-md`.
- Added backdrop click-to-dismiss (`if (e.target === e.currentTarget)`).
- Added `Escape` key listener for immediate dismissal.
- Added background body scroll locking (`document.body.style.overflow = 'hidden'`) while modals are active.
